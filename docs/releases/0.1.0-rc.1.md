# PaperRoute Tracker v0.1.0-rc.1

This is the first release candidate for PaperRoute Tracker v0.1.0.

RC.1 moves PaperRoute from feature development into release validation, with a particular focus on protecting manuscript data and proving the installed update path from the alpha series.

## Highlights

- Automatic recovery from a valid `manuscripts.bak` when the primary manuscript database is missing, blank, or corrupt.
- Preservation of damaged primary data for recovery and diagnostics.
- Fail-closed startup when manuscript storage cannot be loaded safely.
- Strict validation of storage schema metadata while remaining on **schema 1**.
- Deterministic Needs Attention business logic with expanded automated coverage.
- Additional regression coverage for imports, correspondence, linked files, and managed-copy rollback.
- Release packaging now verifies that the Git tag, compiled ProductVersion, and Velopack package version agree.

## Automated validation

RC.1 has **48 automated regression tests** covering persistence, recovery, migration, schema validation, backup and restore, spreadsheet import, manuscript route relationships, correspondence, managed files, linked files, and Needs Attention rules.

## Primary RC.1 update test

The main RC.1 validation is an in-place Preview-channel upgrade from installed `0.1.0-alpha.3`.

After RC.1 is published:

1. Launch installed `0.1.0-alpha.3`.
2. Choose **Settings -> Check for Updates...**.
3. Confirm PaperRoute offers `0.1.0-rc.1`.
4. Review the release notes and apply the update.
5. Allow PaperRoute to restart.
6. Confirm Diagnostics reports `Version: 0.1.0-rc.1`, `Installed build: Yes`, `Update channel: Preview`, and `Storage schema: 1`.
7. Confirm the manuscript library and settings remain intact.
8. Compare post-update hashes with the saved pre-update validation manifest.

## Release-candidate status

RC.1 is not the final stable v0.1.0 release.

Remaining work includes updater and recovery validation, diagnostics and encoding cleanup, accessibility and keyboard review, UI polish, documentation review, clean-machine installation testing, and final packaging/signing review where practical.

No storage-schema change is introduced solely for the RC transition.
